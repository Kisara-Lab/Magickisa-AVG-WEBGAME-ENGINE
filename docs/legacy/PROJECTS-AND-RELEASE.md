# Legacy 工程迁移、发行与故障处理

## 独立项目与目录

工程管理提供创建、打开、导入、导出与打开目录，不提供项目删除、合并或跨模式转换。

```text
workspace-projects/<workspaceId>/
  workspace.json   工作区登记信息（默认工作区的登记方式不同）
  project.json     当前工程
  content/         配套创作数据，兼容档包含章节等数据
  public/          当前工程素材
  backups/         保存前的历史内容备份
  dist/            构建后的游戏
```

默认工作区目录分别为 `default-modern` 与 `default-release`，其接口标识为 `builtin-modern`、`builtin-release`。独立工作区采用随机 ID，不等于游戏内部 project.id；同包重复导入也不会覆盖原工程。

浏览器草稿和偏好按工作区、模式及标签页隔离。切换项目先处理保存／放弃／取消，导航历史会清空；不同标签页可以打开不同工程，避免并发编辑同一个工程。

## 整体工程导出

1. 处理未应用的 JSON、子 JSON 与无效数字。
2. 在工程页进入“项目管理与整体导入导出”。
3. 检查当前工程，查看场景数、素材数、预计大小、外链与缺失资源。
4. 修复阻塞错误。兼容档缺失外置歌词但有内嵌字幕时可作为警告。
5. 明确是否包含未保存修改，开始导出；等待任务完成。
6. 保存 ZIP 与 SHA256 校验文件到工程目录以外的归档位置。

导出默认包含当前**已应用但可能未保存**的表单修改，不要求先覆盖磁盘。未应用输入不属于该快照；有未应用 JSON 时导出被阻止。

```text
manifest.json   包格式、Studio 版本、模式、文件列表与逐文件 SHA256
project.json    已应用工程快照
content/        必要配套创作数据
public/         全部项目素材，包括未使用素材和大音频
README.txt      导入说明、联网依赖与警告
```

包格式为 `magickisa-project` 版本 1，Legacy 的 studioVersion 为 `1.0.0`。不含引擎、依赖、玩家存档、浏览器草稿、界面偏好、历史备份、构建输出或历史程序 bundle。外链不自动下载。

导出会检查磁盘 revision 和打包期间文件变化。出现冲突时重新加载、处理差异，再重新检查导出；不要把失败任务的文件作为完整归档。

## 导入与换电脑

1. 另一台电脑先安装 Legacy 开发工具并启动 Studio。
2. 选择／拖入 `.magickisa.zip`，等待临时检查。
3. 查看模式、内容摘要、外部依赖与警告。
4. 确认名称，建立并打开独立新工程。同名时自动加序号。
5. 检查人物、背景、OP／ED 与音频，继续编辑、保存和构建。

内部稳定 ID 保留，工作区重新生成；原项目不被修改。导入不受单素材 8 MB 限制，但整个 ZIP 限制 **2 GiB**、解压总量 **8 GiB**、文件数 **50,000**。

导入拒绝校验不符、清单外文件、路径越界、符号链接、重复路径、大小写／Unicode 冲突及不支持的版本。不要修改 manifest 来绕过检查，也不要把任意文件夹压成 ZIP 当作工程包。

### JSON 导入导出是什么

高级 JSON 导出不含素材，适合查看或修改工程数据；导入会成为当前工程的编辑草稿，需要应用、检查和保存。它不能替代完整工程迁移，也不是给已有工程做自动合并的入口。

## 磁盘备份与恢复

每次磁盘保存前备份旧内容，路径通常是 `backups/studio-<profile>-<时间>-<随机值>/`。备份包含工程内容，兼容档还包含相关 content JSON；**不包含全部素材**。当前没有自动保留策略和一键恢复，不会自动清理历史备份。

恢复前：关闭 Studio 服务，复制整个项目目录到另一位置，保留当前素材与异常现场。然后选定同一项目、同一模式的备份：

1. 将备份里的 `project.json` 复制回项目根目录。
2. 对兼容档，同时把备份中原属 `content/` 的 JSON 放回该目录，例如 `engine-story.json` 与 `script.json`。不要把所有备份 JSON 都扔进根目录。
3. 核对原文件归属；有自定义同名内容文件或不确定映射时先对照完整项目副本，不猜测覆盖。
4. 重新启动，若出现浏览器草稿恢复提示，先保留草稿副本，再决定丢弃或另行整理，避免又覆盖刚恢复的磁盘状态。
5. 检查、预览并保存；现代档由正常服务流程重新生成所需内容。

捕获到的写入错误会尝试回滚，但强杀或断电可能中断多文件写入，不保证断电事务恢复。完整迁移与长期归档优先使用已验证的整体工程包。

## 构建与部署

推荐使用 Studio 的 **检查内容 → 保存工程 → 构建发行包**，查看目标工程、进度和日志。命令行构建读取磁盘，不包含浏览器未保存修改。

默认工作区：

```sh
npm run build
# 默认发行兼容档
npm run build:release
```

指定独立工程，PowerShell：

```powershell
$env:MAGICKISA_WORKSPACE = "替换为工作区ID"
npm run build
# 发行兼容工程使用 npm run build:release
Remove-Item Env:MAGICKISA_WORKSPACE
```

macOS／Linux：

```sh
MAGICKISA_WORKSPACE="替换为现代工程工作区ID" npm run build
MAGICKISA_WORKSPACE="替换为兼容工程工作区ID" npm run build:release
```

构建模式必须匹配工程。独立项目输出 `workspace-projects/<workspaceId>/dist/`，默认两套分别输出 `default-modern/dist/`、`default-release/dist/`。

将 **dist 内的内容**部署到静态网站根目录，经 HTTP(S) 访问；不要双击本地 index.html。资源按站点根路径解析，子路径部署需要额外路径配置。部署后检查手机布局、音频、开场、分支、结局和刷新读档。玩家只需浏览器，无须安装 Node.js。

`npm run build:studio` 只构建编辑器前端，不是游戏发行命令；其 `dist-studio/` 不能替代完整本地开发服务。

## 玩家存档与工程存储

玩家存档保存在玩家所用浏览器中，与 Studio 草稿、工程 JSON、磁盘备份不同；工程包不包含玩家进度。需要迁移玩家进度时使用游戏内存档导出／导入，并检查作品归属。

- 工程 ID、内容版本用于检查存档归属；改标题不等于新作品。
- 新存档含场景／台词 ID 顺序签名，重排可能拒绝错位加载；旧存档缺少签名时仍按旧规则读取。已发行内容发生变化应提升工程版本，存档不自动迁移。
- 同包导入保留内部 ID，同域名部署的副本可能共享存档标识；独立作品使用不同工程 ID 或独立来源。
- 玩家存档没有跨标签页协调，请只保留一个游戏标签页游玩同一工程与槽位。
- 读取损坏或写入失败时先导出可用进度和原记录，不反复清空浏览器数据；临时周目不等于自动保存成功。

## 常见故障

| 问题 | 处理顺序 |
| --- | --- |
| 连接拒绝 | 检查服务终端仍在运行，使用实际地址与端口 |
| 草稿已保留但文件没变化 | 按 Ctrl+S；草稿只在浏览器 |
| 修改未反映到预览 | 应用待处理 JSON，再按 Ctrl+Enter |
| 409 版本冲突 | 先保留自己的内容副本，重新加载磁盘，比较后重新应用；不删除文件强制覆盖 |
| localStorage／IndexedDB 失败 | 检查浏览器权限和空间，先导出可用内容；不能把失败提示视为已保存 |
| 全部分支消失，故事停住 | 检查条件、once、next 与目标进入条件，确认是否有合法后备路线 |
| 选择后没跳转但变量变了 | 兼容档先执行选择效果与 once，再检查目标门槛，参见剧情时机说明 |
| 素材上传失败 | 确认类型、非空和 8 MB 上限；大文件放入当前项目 public |
| 包导入失败 | 核对版本、限制和 SHA256，使用真正的整体工程包，查看首个诊断 |
| 构建失败 | 先检查并保存，核对模式与工作区，检查缺失资源、磁盘空间和日志 |
| 发行后资源失效 | 检查站点根路径、文件名大小写、外链和浏览器音频策略 |

## 给自行修改源码的开发者

在 Legacy 源码目录顺序执行：

```sh
npm ci --include=dev
npm run typecheck
npm test
npx playwright install chromium
npm run test:studio
npm run notices:check
npm run build:studio
```

Linux 可用 `npx playwright install --with-deps chromium` 安装系统依赖；也可设置 `MAGICKISA_BROWSER` 指向本机 Chromium／Edge 可执行文件。写入工程的验收顺序执行，先备份自己的工程。

源码入口为 `src/engine/`（现代运行时）、`src/compat/release/`（发行兼容运行时）、`src/studio/`（共享工作台）、`scripts/`（本地服务与打包）。扩展时保留稳定 ID、各自格式、预览协议和各自效果时机；本版本以源码使用，不提供 npm 发布包或云端协作服务。
