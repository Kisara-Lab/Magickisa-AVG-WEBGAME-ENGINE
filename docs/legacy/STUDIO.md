## 工作台与编辑定位

工作台按创作、资源、工程组织入口，左侧章节导航、中间编辑、右侧预览；左右面板可折叠、调宽与恢复默认布局。布局偏好保留在浏览器，不修改游戏内容。

- `Ctrl+K`：搜索操作、场景、台词、人物、资料与素材。
- `Ctrl+S`：保存当前工程到磁盘。
- `Ctrl+Enter`：手动更新真实预览。
- `Esc`：关闭浮层。
- 返回／前进：当前标签页最近 30 个编辑位置；切换工程清空导航历史。
- 帮助抽屉：当前页步骤、快捷键和高级字段位置。
- “在哪里使用”：查询已应用草稿中的明确引用，可跳转再返回；未应用 JSON 不参与计算。

高级属性按需展开，条件、效果、图层、完整 JSON 与运行变量调试仍可编辑。输入框中的 `Ctrl+Z` 保留文字撤销；工程修改使用工作台撤销／重做，最近 40 步，连续输入以失焦、换字段或停顿 800ms 为归组边界。

## 做一个三场景故事

目标：入口提供“查看信封”和“离开”两个选择，分别跳到线索场景和结局场景。

1. 创建空白工程，先保留它的内部工程 ID 和版本。
2. 将起始场景标题改为“门厅”，第一行写“桌上放着一个未拆的信封。”。
3. 新建“信封”和“离开”场景，各写一句台词，记录三者实际稳定 ID。
4. 在门厅新增两个分支，文案分别为“查看信封”“离开”，目标选择对应场景。
5. 给“信封”设置下一场景为“离开”。
6. 在结局场景填写结局标识，例如 `left-house`；它是成就名称，不是跳转 ID。
7. 检查工程起始场景仍指向门厅，保存并从头预览两条路线。

### 可复制的节点数据

下面是完整的 `nodes` 数组示例，不是整个工程。可在一个新建的测试工程 JSON 页面中替换 `nodes`，并把 `startNodeId` 设为 `hall`，其余必需顶层字段保持原值。应用、检查并保存后预览。

```json
[
  {
    "id": "hall",
    "title": "门厅",
    "chapter": "第一章",
    "lines": [{ "id": "hall-1", "text": "桌上放着一个未拆的信封。" }],
    "choices": [
      {
        "id": "inspect-envelope",
        "label": "查看信封",
        "target": "envelope",
        "once": true,
        "effects": [{ "type": "set", "key": "foundLetter", "value": true }]
      },
      { "id": "leave-house", "label": "离开", "target": "exit" }
    ]
  },
  {
    "id": "envelope",
    "title": "信封",
    "chapter": "第一章",
    "lines": [{ "id": "envelope-1", "text": "信纸上写着：黄昏之前回来。" }],
    "next": "exit"
  },
  {
    "id": "exit",
    "title": "离开",
    "lines": [{ "id": "exit-1", "text": "你走出了屋子。" }],
    "ending": "left-house"
  }
]
```

这组节点不依赖场景效果字段，可用于两种模式的新建测试工程。不要直接替换已有作品的节点数组；删除旧节点可能破坏其他引用和存档。

## 场景、台词与跳转

| 字段 | 作用 |
| --- | --- |
| 场景 `id` | 稳定身份，供起点、跳转、资料解锁等引用 |
| `title`、`chapter` | 显示标题与章节组织，不代替 ID |
| 台词 `id`、`text` | 台词身份与正文；保留 ID 有利于存档与引用稳定 |
| `speaker` | 说话人文字；逐句设置优先于场景说话人 |
| `next` | 没有可用选择时尝试进入的下一场景 |
| `choices[].target` | 玩家选择该分支后尝试进入的目标 |
| `condition` | 场景进入／台词显示／分支可选条件，取决于字段所在位置 |
| `once` | 分支只允许使用一次 |
| `ending` | 自由命名的结局标识 |

流程图用于搜索、缩放、适应视图、定位当前和查看相邻连接。点击节点后选择“编辑选中场景”，通过剧本表单修改 `next` 或分支目标。虚线表示该连接含条件、一次性限制或目标条件，不代表当前必然可走；筛选隐藏的节点不等于工程中不存在。

删除场景前查看引用，处理受影响的起点、跳转和资源解锁。不要通过随意改 ID 绕过引用检查。

## 条件速查

条件不存在时视为满足。字段填写 JSON 时保留字符串引号、布尔类型和数字类型。

| 条件 | 示例 | 含义 |
| --- | --- | --- |
| `flag` | `{"type":"flag","key":"foundLetter","equals":true}` | 指定变量等于给定值；省略 equals 时按真值判断 |
| `count` | `{"type":"count","key":"trust","operator":"gte","value":2}` | 数值比较，支持 eq／gt／gte／lt／lte |
| `visited` | `{"type":"visited","nodeId":"envelope"}` | 已访问指定场景；value:false 表示未访问 |
| `all` | `{"type":"all","conditions":[...]}` | 所有子条件满足 |
| `any` | `{"type":"any","conditions":[...]}` | 至少一个子条件满足 |
| `not` | `{"type":"not","condition":{...}}` | 子条件取反 |

表格中的 `...` 是示意，不能原样作为合法 JSON。可复制的组合示例：

```json
{
  "type": "all",
  "conditions": [
    { "type": "flag", "key": "foundLetter", "equals": true },
    { "type": "not", "condition": { "type": "visited", "nodeId": "exit" } }
  ]
}
```

空 `all` 恒真，空 `any` 恒假。`count` 将变量转为数字，缺失变量按 0；请避免混用数字与任意字符串。跨两种模式的变量等值条件建议使用字符串、数字、布尔或 null；复杂对象等值在两个运行时中的实现不同，不适合作为通用逻辑约定。

## 效果速查

效果为按顺序执行的数组；变量仅写入玩家运行状态，填写条件本身不会初始化它。

| 类型 | 必需参数 | 用途 |
| --- | --- | --- |
| `set` | key、value | 设置变量 |
| `toggle` | key | 翻转变量真值 |
| `increment` | key、amount | 数值增减，负数表示减少 |
| `addToList`／`removeFromList` | key、value | 操作列表变量 |
| `unlockMaterial` | id | 解锁已登记资料 |
| `markRead` | id | 标记资料已阅读 |
| `appendNote` | text | 添加剧情笔记 |
| `setAudio` | trackId | 播放 audio 数组中已登记的音轨 ID |

例如，分支的“选择后效果”可以填写：

```json
[
  { "type": "set", "key": "foundLetter", "value": true },
  { "type": "increment", "key": "trust", "amount": 1 },
  { "type": "appendNote", "text": "发现一封约定黄昏见面的信。" }
]
```

### 效果执行时机

**现代档：** `onEnter` 在进入节点时执行，`onComplete` 在节点完成时执行，并用完成状态避免重复完成。可用分支的计算考虑完成效果，再模拟该分支效果检查目标进入条件；选择时正式执行。不要为了初始化变量把本应进入时执行的效果写进完成效果。

**发行兼容档：** 使用节点 `effects`。节点结束继续时执行当前节点效果；通过选择成功进入目标时，立即执行目标节点效果，之后该目标节点结束继续时仍可能再次执行。选择操作先记录 once 并执行选择效果，再检查目标进入条件；进入失败会留在原节点，但选择副作用已发生。终点反复继续可能重复执行节点效果，因此积分累加、扣费等配置应特别检查。

这一行为可在冻结版 [runtime.js 的 choose 与 advance 方法](https://github.com/Kisara-Lab/Magickisa-AVG-WEBGAME-ENGINE/blob/v1.0legacy/src/compat/release/engine/runtime.js)核对；不要假设兼容档的场景效果只在节点完成时执行一次。

两种模式下，可选分支全部隐藏或一次性分支用尽后会尝试 `next`，目标条件不满足则停留。请提供合理的后备路线，或确认该处确为有意设计的终点。

## 玩家输入与资料

台词可配置 `input: { "key": "playerName", "label": "你的名字", "maxLength": 40 }`，结果写入同名变量。空白或超长内容不能推进。中文输入法、空格与方向键保留正常文字输入行为。

资料包含 `id`、`title`、`body`、`category`，可设置 `unlockNode` 与 `unlock` 条件，也可由效果解锁。现代档自动解锁要求指定的访问门槛与条件同时满足；未设置门槛的资料可能直接公开。兼容档的历史解锁规则请结合检查提示与真实预览确认，尤其注意未配置解锁且没有同名场景的条目。

## 保存、草稿与预览

| 状态 | 实际含义 |
| --- | --- |
| 草稿已保留 | 浏览器 IndexedDB 副本，停止输入 500ms 后保存，不代表磁盘已写入 |
| 工程已保存 | 已应用内容已经写入当前项目目录 |
| 预览已同步 | 当前已应用内容已发送给真实运行时 |
| 未应用 JSON／子 JSON／数字 | 保留原有效工程，输入尚未进入工程 |

完整 JSON 编辑：先保存／导出旧工程副本，修改后点击应用，再检查、预览与保存。子 JSON 有自己的应用入口；错误的数字输入不会写入 0 代替原值。存在未应用 JSON 时先处理，不要把它误认为已包含在发行中。

预览不随每次输入自动重启；使用预览按钮或 `Ctrl+Enter` 更新。可切换桌面／手机尺寸、放大并修改调试变量；预览使用内存存档，不写真实玩家进度。检查条件时从正确状态走完实际路线，不仅看流程图。
