**用网页技术制作、编辑和发行 AVG / 视觉小说。**

MAGICKISA 是由 **Kisara-Lab** 维护的网页 AVG 引擎与可视化创作工作台。基于 React、TypeScript 和 Vite，提供剧情分支、人物立绘、条件与效果、特殊演出、存档及浏览器运行能力；配套 **MAGICKISA Studio** 将剧本、资源、演出、预览和发行放在同一个工作台中。

适合希望在浏览器中发布文字冒险、分支叙事或视觉小说的创作者，也适合需要直接扩展运行时与编辑器的开发者。

## 快速开始

### 环境要求

- **Node.js 22 或更新版本**，以及 npm。
- Windows、macOS 或 Linux 本地开发环境。
- 推荐使用最新版 Chromium、Microsoft Edge 或 Google Chrome。

Studio 的保存、素材上传和构建由本地 Node 服务完成；浏览器需要允许站点使用 IndexedDB 与 localStorage，以保留草稿和界面偏好。

### 安装并启动

```sh
git clone https://github.com/Kisara-Lab/Magickisa-AVG-WEBGAME-ENGINE.git
cd Magickisa-AVG-WEBGAME-ENGINE
npm ci
npm run dev
```

启动后会尝试打开 Studio，也可以手动访问终端显示地址下的 `/engine.html`，通常为：

```text
http://127.0.0.1:5173/engine.html
```

端口占用时以终端实际输出为准。首次进入项目管理后，输入名称、选择运行模式，点击“创建并打开”；也可以导入已有 `.magickisa.zip` 工程包。

如果希望使用本次开源版本，在克隆后执行以下命令，再安装依赖：

```sh
git switch --detach v1.0.0
```

计划修改引擎源码时，可在该版本上建立自己的开发分支：

```sh
git switch -c my-development v1.0.0
```

## 两种运行模式

| 模式 | 用途 | 工作台启动命令 |
| --- | --- | --- |
| 现代版 | 使用 TypeScript 运行时进行新工程开发 | `npm run dev` |
| 发行兼容版 | 编辑和运行采用兼容格式的工程，保留兼容运行时的效果执行时机 | `npm run dev:release` |

两种模式共用 Studio。创建工程时选择模式；导入工程包时使用包内记录的模式。现代工程使用 `schemaVersion: 2`，兼容工程沿用兼容格式，当前不提供自动互转。

首次启动会生成两套默认空白工作区。它们只含满足格式要求的最小场景，不含示例剧情或媒体；也可以关闭项目管理，直接编辑相应模式的默认工作区。

## 从空白工程到可玩游戏

1. **创建工程**：输入名称、选择运行模式，建立独立工作区。
2. **编写剧本**：编辑起始场景与台词，新增场景，再设置下一场景或分支目标。
3. **整理资源**：上传背景、立绘、表情和音频，在相应字段通过素材选择器回填。
4. **添加交互**：按需展开条件、效果和图层属性，设置变量、分支条件与资料解锁。
5. **编排演出**：需要时编辑献词、OP 镜头、字幕或 ED，不要求每个游戏都配置全部演出。
6. **预览验证**：点击预览或按 `Ctrl+Enter`，在真实运行时中检查当前内容。
7. **保存与发行**：检查内容、保存工程，再构建发行包；迁移到另一台电脑时使用整体工程导出。

场景与台词通过稳定 ID 关联。修改标题不会替代 ID；手工编辑 JSON 时，应同时检查跳转、条件和效果中的引用。

## Studio 使用说明

### 工作空间与导航

工作台按创作、资源与工程组织功能入口，提供章节导航、编辑区与预览区。侧栏和预览面板可折叠、调整宽度，也可以恢复默认布局。

- 命令面板统一搜索操作、场景、台词、人物、资料和素材。
- 返回/前进保留当前标签页最近 30 个编辑位置；切换工程会清空这段导航历史。
- “在哪里使用”根据当前已应用工程显示引用，可跳转到相关编辑位置。
- 页头帮助介绍当前页面的常用步骤、快捷键和高级功能位置。
- 常用字段直接展示，高级参数在当前页面按需展开；完整 JSON 编辑始终保留。

### 剧本、人物与素材

剧本支持按章节浏览、搜索场景与台词，并在当前行附近新增、复制、移动或删除台词。连续输入会合并撤销记录，切换字段、失焦或停止输入 800ms 时结束当前输入组。

人物、表情和资料采用列表与选中项编辑。背景、立绘和演出音频等字段可以打开素材选择器，搜索、预览或试听后回填。删除场景仍需通过已有跳转引用检查。

单素材上传上限为 **8 MB**。大音频可以直接放入当前工程的 `public/` 目录，再填写工程内的资源路径。例如：

```text
workspace-projects/<workspaceId>/public/audio/theme.mp3
```

对应工程字段填写 `/audio/theme.mp3`。不要填写本机磁盘绝对路径。素材路径相对于该工程的 `public/`，同名路径在不同工程中分别解析。

### 献词、OP 与 ED

献词通过页面列表与单页编辑编排；OP/ED 提供时间轴、字幕列表和当前项参数。可以缩放时间轴、点击定位、调整字幕时间，并通过数字输入进行精确修改。

OP 镜头支持排序与前后移动，播放节奏沿用运行时规则，不提供独立镜头时长。ED 保留双语字幕、鸣谢模式及相关参数。兼容工程缺失外置歌词、但已有内嵌字幕时会显示说明并继续使用内嵌字幕。

### 快捷键

| 快捷键 | 操作 |
| --- | --- |
| `Ctrl+K` | 打开命令面板 |
| `Ctrl+S` | 保存当前工程 |
| `Ctrl+Enter` | 应用当前内容到预览 |
| `Esc` | 关闭浮层 |

输入框保留正常文字编辑行为。预览支持桌面、手机尺寸和放大模式；输入时不会自动重启剧情，需要手动更新画面。

### 草稿、保存与预览的区别

| 状态 | 含义 |
| --- | --- |
| 草稿已保留 | 浏览器 IndexedDB 中已有可恢复副本，不代表文件已保存 |
| 工程未保存 / 已保存 | 当前已应用编辑内容是否写入工程文件 |
| 预览待更新 / 已同步 | 当前预览是否使用最新已应用内容 |
| 未应用 JSON | JSON 页面存在尚未应用的原始输入，保存、导出和构建前需先处理 |

停止输入 500ms 后保留浏览器草稿。发现可恢复草稿时可选择恢复或丢弃；草稿按工程与标签页隔离。清理浏览器数据会丢失浏览器草稿，重要内容应保存到磁盘并导出工程包。

外部程序修改工程后，保存接口可能返回 **409 版本冲突**。此时重新加载并处理差异，草稿恢复不会跳过服务器版本检查。存储失败也会明确提示，不能将失败状态视为已备份。

## 工程导入导出与备份

### 整体工程包

在“工程”页打开“项目管理与整体导入导出”，按 **检查 → 查看摘要 → 导出** 操作。导出当前已应用工程快照，包括未保存的表单修改和全部项目素材，也包含未使用素材与大音频。

工程包使用标准 ZIP，推荐扩展名为 `.magickisa.zip`：

```text
manifest.json   包版本、运行模式、文件清单、大小与逐文件 SHA256
project.json    当前已应用工程快照
content/        配套创作数据，兼容工程包含章节等内容
public/         全部项目静态素材
README.txt      导入说明、外部依赖及导出警告
```

下载时另提供整个 ZIP 的 SHA256 校验文件。包中不包含引擎、编辑器源码、依赖、浏览器草稿、偏好、玩家存档、历史备份或发行输出。外部资源保留原链接并提示联网依赖，不会自动下载。

### 导入为独立工程

在另一台装有兼容版本 Studio 的电脑上选择或拖入工程包，经临时检查后确认名称并打开。导入会验证版本、清单、文件校验值、工程结构和本地引用，成功后创建独立工作区。

重复导入同一包也不会覆盖旧项目；工作区 ID 与游戏内部 `project.id` 分开，游戏稳定 ID 保留。当前不提供项目合并、覆盖恢复或任意 ZIP 文件夹识别。

| 限制 | 数值 |
| --- | --- |
| 单素材上传 | 8 MB |
| 工程 ZIP 大小 | 2 GiB |
| 解压总量 | 8 GiB |
| 包内文件数量 | 50,000 |

损坏包、越界路径、符号链接、重复条目、大小写冲突、清单外文件及校验不符会被拒绝。未应用 JSON、结构错误、必要本地资源缺失或版本冲突会阻止整体导出。

高级 JSON 导入导出仅处理工程数据，**不含素材**。迁移完整项目请使用整体工程包。`workspace-projects/` 被 Git 忽略，推送引擎仓库不会替你备份游戏内容。

### 保存前备份与手动恢复

项目管理面板提供“打开保存备份目录”。每次保存前会复制磁盘中的旧版本，目录名含时间戳和随机 ID，避免重复覆盖。备份只涵盖工程内容文件，不包含全部素材；完整迁移和长期归档仍应导出工程包。

恢复时先关闭 Studio，复制整个项目目录作为保护副本，再从选中的备份目录恢复：现代版将 `project.json` 放回项目根目录；发行兼容版将 `project.json` 放回项目根目录，其余备份文件放回 `content/`。重新启动并加载工程，检查内容后再保存、预览和构建。**不要在 Studio 仍打开旧草稿时直接覆盖文件并继续保存。**

备份不会自动删除，也没有一键回退或保留数量设置。长期使用会占用磁盘；确认完整工程包可用后，可在文件管理器中手动清理不再需要的旧备份。本轮保留人工清理策略，避免自动删除恢复点。

### 玩家存档的兼容边界

现代版使用 v2 存档，发行兼容版使用 v1 存档，两种格式不能直接互导。存档中的 `projectId` 和 `contentVersion` 必须与工程匹配；本仓库不附带旧游戏专用的迁移工具，也不自动转换内容版本。准备更新工程 `version` 前，应明确是否允许旧存档继续使用，并为内容变化设计和验证自己的迁移方案。

发行兼容版的新存档按工程 ID 隔离。旧的 `magickisa:view` 和 `magickisa-avg:slot:auto` 全局记录保留原样，不自动认领到当前作品。需要使用旧 v1 存档时，先自行导出对应 JSON，通过游戏的存档导入入口确认归属；系统会检查节点、行号、历史、变量和音量等结构。无法读取的存档会提示错误并保留原数据，在用户导入有效存档或明确重新开始前，不自动覆盖该记录。

旧全局记录可能属于其他作品，游戏的重新开始不会清除它。需要释放浏览器空间时，先导出这些记录，再在浏览器开发者工具的存储面板中手动删除对应键。Studio 预览的存档使用独立内存，不写玩家存档。同一工程包的副本保留内部工程 ID；若把它们部署在同一域名下，将共享玩家存档标识，独立作品应使用不同工程 ID 或独立站点来源。当前玩家存档没有跨标签页协调，请避免同时在多个标签页游玩同一工程和槽位。

磁盘备份支持异常捕获后的回滚；进程被强制结束或断电时，多文件写入仍可能中断，需要按上述步骤人工恢复备份。本版本不提供断电事务恢复保证。

### 条件分支与玩家输入

两种模式下，选项全部被条件隐藏或一次性选项用尽后，会尝试进入 `next`；若没有 `next` 或其进入条件不满足，则停留当前节点。校验会对“全部选项可能不可用、又没有无条件后备场景”的配置给出警告，合法结局仍可保留。兼容版节点 `effects` 的执行时机保持原行为。

台词输入使用 `input: { key, label, maxLength }`，写入同名变量。空白和超长文本不能推进；输入框内空格、方向键与中文输入法保留文字编辑行为。逐句 `speaker` 优先于场景的说话人。资料和音乐的解锁场景使用稳定场景 ID，与场景在数组中的位置无关。

## 构建与部署

### 推荐：在 Studio 中发行

按照 **检查内容 → 保存工程 → 构建发行包** 操作，查看警告、错误、目标工程、输出目录、进度和日志。

独立工程输出位于：

```text
workspace-projects/<workspaceId>/dist/
```

默认现代版和兼容版分别输出到 `workspace-projects/default-modern/dist/`、`workspace-projects/default-release/dist/`。

将 `dist/` 中的内容部署到静态网站的根目录，通过 HTTP(S) 访问；不要直接双击 `index.html`。当前资源路径按站点根目录解析，部署到子路径需要额外处理路径配置。带外部链接的资源依赖相应外部服务。

### 命令行构建

```sh
# 默认现代版工作区
npm run build

# 默认兼容版工作区
npm run build:release
```

构建指定独立工程时，设置 `MAGICKISA_WORKSPACE` 为其工作区 ID，并使用匹配的运行模式。命令行构建读取磁盘工程，不包含尚未保存的浏览器表单修改。

PowerShell 示例：

```powershell
$env:MAGICKISA_WORKSPACE = "替换为工作区ID"
npm run build
# 兼容工程改用 npm run build:release
Remove-Item Env:MAGICKISA_WORKSPACE
```

macOS / Linux 示例：

```sh
MAGICKISA_WORKSPACE="替换为工作区ID" npm run build
# 兼容工程使用 npm run build:release
```

`npm run build:studio` 用于检查编辑器前端的生产构建，输出为 `dist-studio/`。实际编辑仍需要本地 Node 服务，静态部署该目录不能替代保存、上传、工程管理和构建服务。

## 源码结构与扩展

```text
src/
  engine/           现代 TypeScript 运行时与渲染组件
  compat/release/   发行兼容运行时及界面
  game/             现代通用游戏界面
  studio/           两种模式共享的编辑工作台
scripts/            内容生成、项目上下文、导入导出与验收工具
tests/              使用最小生成数据的通用运行时测试
workspace-projects/ 本地工程、素材、备份与构建输出（运行时生成）
```

现代运行时的入口为 [`src/engine/index.ts`](src/engine/index.ts)，公开 `AvgEngine`、`EngineStore`、`EngineSession`、`StoryRuntime`、校验、存档和渲染组件等能力。条件与效果支持处理器扩展；人物渲染提供 Live2D 适配器注册接口。

Studio 的共享组件位于 [`src/studio`](src/studio)，本地服务与工程包处理位于 [`scripts`](scripts)。扩展时应保持游戏 schema、稳定 ID、预览消息协议及两种模式各自的效果执行时机兼容。

本仓库尚未发布 npm 包，当前以克隆源码的方式开发和使用。不附带原游戏专用存档迁移、原发行 bundle 或画面对照基准，也不提供云协作与在线托管服务。

## 开发命令与验收

| `npm ci` | 按锁文件安装依赖 |
| `npm run dev` | 启动现代版 Studio |
| `npm run dev:release` | 启动兼容版 Studio |
| `npm run typecheck` | TypeScript 类型检查 |
| `npm test` | 通用运行时测试 |
| `npm run test:studio` | 两种模式的浏览器与工程迁移验收 |
| `npm run build:studio` | 编辑器前端生产构建 |
| `npm run build` | 默认现代版或指定现代工程的发行构建 |
| `npm run build:release` | 默认兼容版或指定兼容工程的发行构建 |
| `npm run content:validate` | 校验默认现代版工程内容和资源 |
| `npm run content:build` | 为默认现代版生成运行内容 |

运行浏览器验收前安装 Chromium：

```sh
npx playwright install chromium
npm run typecheck
npm test
npm run test:studio
npm run build:studio
```

也可用 `MAGICKISA_BROWSER` 指定本机 Chromium / Edge 可执行文件。Linux 环境需要系统依赖时，使用 `npx playwright install --with-deps chromium`；CI 固定使用 Ubuntu 24.04 和 Node.js 22。

Studio 验收覆盖两种模式的空白工程创建、未保存快照导出、SHA256、独立导入、中文空格路径、未使用素材、大于 8 MB 的素材、继续编辑、保存、场景与特殊演出预览、实际发行构建、启动标识动画和 390px 布局。涉及工程写入的验收应串行执行。

## 常见问题

### 编辑与播放的边界说明

- **数字框**：必填数字清空或越界时显示“尚未应用”，工程保留上次有效值；图层可选数字清空表示恢复运行时默认值，不会写入 `0`。坐标仍支持画面外位置。子 JSON 编辑有独立的“应用此项”，未应用文字不会因同页其他字段更新而被覆盖。
- **撤销**：工具栏和命令面板可撤销／重做工程修改，保留最近 40 步；同字段连续输入按 800ms 归组。输入框内的 `Ctrl+Z` 保留浏览器文字撤销；工程级撤销会恢复有效场景和台词选中位置。工程级 JSON 有未应用输入时保持原文，工程撤销不会替作者应用该输入。
- **身份与存档**：新增场景、台词、人物、资料等采用随机 ID，删除后新建不会复用旧 ID；已有 ID 不变。普通 HTTP 下没有 `randomUUID` 时使用 Web Crypto 的 `getRandomValues` 生成 UUID。修改已发行内容的台词顺序或语义时应提升工程版本，旧存档不自动迁移。
- **条件与流程图**：空 `all` 恒真，空 `any` 恒假。流程图虚线表示有条件的连接，只描述配置，不保证当前变量下可通行。内容检查会提示可能没有可用分支／回退的场景，包括目标场景的进入条件。
- **发行兼容时机**：兼容版先应用选项效果及 `once`，再检查目标进入条件；失败时仍留在原场景。兼容版终点再次继续可能重复执行场景效果。Studio 对这些配置给出警告，保留原发行执行规则。现代版的进入／完成效果沿用现代运行时规则。
- **演出元数据**：`presentation` 与 `media` 决定 OP/ED 播放；`sequenceId` 为保留元数据，不对应独立序列注册表。`ending` 是自由命名的结局成就标识，不是场景或资料引用。
- **音频**：`setAudio` 引用 `audio[]` 中注册的 ID；两种模式均优先播放指定音轨，否则使用章节音乐规则。曲目音量与全局音量相乘，静音同时作用于鉴赏曲目。打开音乐鉴赏会暂停章节 BGM，同时只播放一首鉴赏曲目；现代版调音量不重建 BGM。
- **玩家笔记**：兼容版玩家输入单独保存为 `playerNotes`，与剧情 `appendNote` 内容分别显示；旧存档缺少此字段时按空笔记读取。兼容版剧情回退保留当前玩家笔记。

自动化验收覆盖数字输入保护、子 JSON 待应用文字、鉴赏音量、两模式台词新增后撤销／重做与命令搜索，以及兼容版笔记推进和刷新后继续。运行时测试另覆盖自跳转存档不重复执行进入效果、旧完成快照修复、随机 ID、条件警告和精确字段位置描述。

### 打开工作台提示连接被拒绝

先确认 `npm run dev` 仍在运行，再使用终端显示的地址访问 `/engine.html`。浏览器书签中的端口可能与本次启动不同；关闭开发服务后，本地工作台就无法连接。

### 为什么仓库里没有完整游戏或素材？

本次开源的是引擎与 Studio。在线成果可访问[《伊尔玛林的黄昏》](https://ilmarin.kisara.info/)，其剧情与素材不包含在源码仓库内。新建工程从最小空白场景开始。

### 已经显示“草稿已保留”，为什么文件没有变化？

草稿保存在当前浏览器；需要点击保存或按 `Ctrl+S` 才会写入工程文件。跨电脑迁移请导出整体工程包。

### 改了内容，预览怎么没变？

预览采用手动更新，避免输入时重启剧情。按 `Ctrl+Enter`，或点击对应预览按钮；JSON 页面还需要先应用输入。

### 大音频无法通过素材上传怎么办？

单素材上传限制为 8 MB。将文件直接放入当前工程的 `public/` 目录，再填写对应资源路径。整体工程包会包含这些文件，仍需满足工程包总量限制。

### 可以用 MIT 引擎制作商业游戏吗？

可以。使用、修改与分发引擎时需保留 MIT 要求的版权及许可声明。你自己的剧情和素材可单独选择许可；第三方组件、外部资源、SDK 和演示站点游戏内容仍适用各自授权。
